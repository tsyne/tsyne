# Three.js + Tsyne Integration Guide

Optional module for running three.js through Tsyne's native OpenGL backend.

## Setup

```bash
# From repo root, or from trine/
./trine/setup-three.sh
```

This clones three.js to `three/` and applies the canvas factory patch.
The integration code stays in `trine/integration/` - it's not copied.

## Architecture

```
three.js (TS) → TsyneBridge → MessagePack → Go Bridge → Fyne Shader → OpenGL
```

Key files in `trine/integration/`:
- `init.ts` - Entry point, exports `setupTsyneThreeJS()`
- `bridge.ts` - TsyneBridge for message passing
- `gl-proxy.ts` - WebGL2 API proxy that batches commands
- `canvas.ts` - TsyneCanvas (fake HTMLCanvasElement)
- `globals.ts` - Browser shims (document, window, etc.)

## Usage

```typescript
import { setupTsyneThreeJS } from '../trine/integration/init';

// Inside your Tsyne app window:
const sendFn = async (msg: any) => {
  return await bridge.send(msg.type, msg.payload || {});
};

const { THREE } = await setupTsyneThreeJS(sendFn, {
  width: 1024,
  height: 768,
  windowId: win.id,
});

// Now use THREE normally
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, 1024/768, 0.1, 1000);
const renderer = new THREE.WebGLRenderer({ antialias: true });
```

## Testing with TsyneTest

### Jest Configuration

Three.js uses ES modules. Required in jest config:

```javascript
transform: {
  '[\\\\/]three[\\\\/]src[\\\\/].+\\.js$': 'babel-jest',
  '^.+\\.ts$': ['ts-jest', { diagnostics: false, isolatedModules: true }]
}
```

### Test Pattern

```typescript
import { TsyneTest } from '../core/src/index-test';

describe('Three.js Demo', () => {
  let tsyneTest: TsyneTest;

  beforeEach(() => {
    tsyneTest = new TsyneTest({ headed: true });  // GL needs real window
  });

  test('renders scene', async () => {
    const { setupTsyneThreeJS } = require('../trine/integration/init');
    // ... setup and test
  });
});
```

### Key Points

1. **Always `headed: true`** - GL rendering requires a real window
2. **Pass `windowId`** - targets the correct Tsyne window
3. **Wait for init** - three.js setup is async

## How the Patch Works

The only modification to three.js is in `src/utils.js`:

```javascript
function createCanvasElement() {
  // Tsyne hook - check for canvas factory
  if (globalThis.__tsyneCanvasFactory) {
    return globalThis.__tsyneCanvasFactory();
  }
  // Normal browser path
  const canvas = createElementNS('canvas');
  canvas.style.display = 'block';
  return canvas;
}
```

The integration code sets up `__tsyneCanvasFactory` before three.js loads,
so three.js gets a TsyneCanvas instead of a browser canvas.

## Common Issues

### Blank Screenshots
- Three.js didn't initialize (check for ES module errors)
- Screenshot taken before first frame
- Wrong windowId passed

### "Cannot find module"
- Run `./trine/setup-three.sh` to clone three.js
- Check import paths
